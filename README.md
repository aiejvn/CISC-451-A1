# CISC 451 — A1: Cross-Domain Text-to-SQL

Repo setup guide. For the write-up (research questions, methodology, results, discussion), see
[`report/main.tex`](report/main.tex) (pulls in `report/RQ1.tex`, `RQ2.tex`, `RQ3.tex`). For a single
notebook that re-runs the whole pipeline and regenerates every table and figure in the report live, see
[`RQ1_RQ2_RQ3.ipynb`](RQ1_RQ2_RQ3.ipynb).

## Layout

| Path | What it is |
|---|---|
| `report/` | The report: `main.tex` + `RQ1.tex`/`RQ2.tex`/`RQ3.tex` (methodology, results, discussion per RQ). |
| `RQ1_RQ2_RQ3.ipynb` | Executable notebook that reproduces every table/figure in the report from a live run. |
| `eval/evalpipeline/` | RQ1/RQ2 pipeline: prompting, generation, Spider evaluation, reasoning-trace analysis. |
| `eval/configs/models.yaml` | The three models compared in RQ1 (repo id, quantization, token budget, thinking mode). |
| `eval/results/` | Generation + evaluation outputs, one subdirectory per model per run. |
| `train/` | RQ3 pipeline: PlanPlay-SQL LoRA fine-tuning (warm start, VBI-FT, self-play) and mock-DB evaluation. |
| `train/runs/` | Fine-tuning outputs: LoRA adapters, training logs, validation history. |
| `spider/` | A copy of the [Spider](https://yale-lily.github.io/spider) dataset repo's files (`evaluation.py`, `process_sql.py`, dev/train splits, DB schemas), included directly rather than as a git submodule. |
| `spider/database/` | Schema-only SQLite DBs (no rows), generated by `build_spider_dbs.py`. Used for RQ1/RQ2. |
| `mock_spider/database/` | Synthetic SQLite DBs with rows, generated by `train.mockdb`. Used for RQ3. |
| `build_spider_dbs.py` | Builds `spider/database/*.sqlite` (schema only) from `spider/evaluation_examples/examples/tables.json`. |
| `build_spider_splits.py` | Re-parses Spider's raw json into `train.json` / `dev.json` below (adds the structured `sql` AST field `evaluation.py` needs). Already run; only needed to reproduce or regenerate them. |
| `train.json` / `dev.json` | Spider train/dev splits (question, gold SQL + parsed SQL AST, `db_id`), produced by `build_spider_splits.py` and committed at the repo root for convenience. |

## Prerequisites

- Linux, Python 3.12.
- An NVIDIA GPU with CUDA. RQ1 generation and RQ3 fine-tuning both need one; RQ2 is pure CPU analysis over
  already-generated outputs. `report/RQ1.tex`'s numbers were produced on a 24 GB RTX 4090; RQ3's were
  produced on an 8 GB GPU — see the VRAM note under RQ3 below if you have less than 24 GB.
- ~15 GB disk for the three HF model checkpoints (bf16), plus a few GB for the Spider/mock SQLite trees.

## 1. Spider dataset files

This is a plain folder (unzip it wherever you like), not a git checkout, so there is no submodule to
fetch: `spider/` already contains everything the pipeline needs from the upstream
[Spider](https://yale-lily.github.io/spider) release (`evaluation.py`, `process_sql.py`,
`evaluation_examples/examples/tables.json`, and the dev/train json it was built from).

If `spider/` ever turns up empty or missing those files (e.g. a future copy of this folder drops it), get
them with:

```bash
git clone https://github.com/taoyds/spider.git
```

and confirm `spider/evaluation.py`, `spider/process_sql.py`, and
`spider/evaluation_examples/examples/tables.json` exist at those paths — nothing below will run without
them.

## 2. Create a virtualenv and install dependencies

```bash
python3 -m venv .venv
source .venv/bin/activate

# torch first, matching your CUDA version (see https://pytorch.org/get-started/locally/), e.g.:
pip install torch --index-url https://download.pytorch.org/whl/cu124

pip install -r eval/requirements.txt
pip install peft           # used by train/ (RQ3 LoRA fine-tuning); not needed for RQ1/RQ2 alone
pip install jupyter ipykernel   # only if you want to run RQ1_RQ2_RQ3.ipynb
```

`eval/requirements.txt` covers RQ1 (generation) and RQ2 (reasoning-trace analysis): `transformers`,
`accelerate`, `bitsandbytes`, `huggingface_hub`, `pyyaml`, `tqdm`, `safetensors`, `nltk`, `scipy`, `pandas`,
`matplotlib`. `peft` is the one extra package RQ3 needs that isn't in that file.

`spider/process_sql.py` needs NLTK's tokenizer data:

```bash
python -c "import nltk; nltk.download('punkt_tab')"
```

## 3. Build the two local SQLite database trees

Spider's official per-database row data isn't distributed with the repo; two local substitutes are built
instead, both idempotent (safe to re-run):

```bash
python build_spider_dbs.py                               # spider/database/*.sqlite — schema only, no rows
SPIDER_DB_DIR=mock_spider/database python -m train.mockdb # mock_spider/database/*.sqlite — schema + synthetic rows
```

- **Schema-only DBs** (`spider/database/`) are used for RQ1 and RQ2. Exact-match scoring is unaffected;
  execution-accuracy numbers against these are schema-level only (every query against an empty table that
  returns nothing scores as correct) — see `report/RQ1.tex`'s Methodology section.
- **Mock DBs with rows** (`mock_spider/database/`) are used for RQ3, where execution-match correctness
  during training/evaluation actually needs real rows to check against. Row values are synthesized from the
  literals each gold query filters on, seeded deterministically — see `train/mockdb.py` and
  `report/RQ3.tex`'s Limitations section for what this approximates and doesn't.

`SPIDER_DB_DIR` controls which DB tree `eval/evalpipeline/common.py` and `train/common.py` point at; it
defaults to `spider/database` when unset. Always set it to `mock_spider/database` for anything under `train/`.

## 4. Model weights

The three models RQ1 compares (`eval/configs/models.yaml`) are ordinary HuggingFace repos:

- `Qwen/Qwen3-0.6B`
- `Qwen/Qwen3-4B`
- `deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B`

Every weight load in this repo (RQ1 generation, RQ3 fine-tuning/evaluation) goes through
`eval/evalpipeline/common.py:resolve_local_path`, which checks `./models/<author>/<name>` first (or
`$MODELS_PATH`, if set, as a different local directory) and only falls back to the HF cache
(`~/.cache/huggingface`) — downloading automatically the first time a model is requested — for whatever
isn't found there. So: drop a model's files under `./models/<author>/<name>/` (e.g.
`./models/Qwen/Qwen3-0.6B/`) to use a local copy, or do nothing and let it download to the HF cache. To
pre-fetch into the HF cache explicitly, or to run fully offline afterwards:

```bash
huggingface-cli download Qwen/Qwen3-0.6B
huggingface-cli download Qwen/Qwen3-4B
huggingface-cli download deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B
```

Pass `--models-path <dir> --local-only` to the scripts below to require weights from a specific local
directory and never touch the network (see `eval/evalpipeline/run.py --help`).

## 5. Running the pipeline

### RQ1 — generate + evaluate all three models on the Spider dev set

```bash
python -m eval.evalpipeline.run \
  --models Qwen/Qwen3-0.6B Qwen/Qwen3-4B deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B \
  --etype all --batch-size 128 --run-id my_run
```

Lower `--batch-size` on a smaller GPU — greedy decoding means batch size only affects speed/memory, not the
generated tokens. Add `--resume` to continue an interrupted run with the same `--run-id`. Output lands in
`eval/results/<author>__<name>/<run-id>/`. See `python -m eval.evalpipeline.run --help` for subsetting
(`--limit`), generation-only / evaluate-later splitting, and repetition-loop stopping (`--loop-stop`).

### RQ2 — reasoning-trace analysis (Token Count, Information Retention, correlations)

```bash
python -m eval.evalpipeline.reasoning_metrics \
  --run eval/results/deepseek-ai__DeepSeek-R1-Distill-Qwen-1.5B/my_run \
  --out eval/results/task2_analysis
```

Writes `per_question_metrics.csv`, `descriptive_stats.csv`, `spearman_correlations.csv`, and
`boxplots.png` to `--out`.

### RQ3 — PlanPlay-SQL fine-tuning and evaluation

```bash
export SPIDER_DB_DIR=mock_spider/database

# 1) supervised warm start (plan format)
python -m train.finetune warm --name e1_plan --fmt plan --epochs 3 --n_train 1500 --lr 2e-4 --bs 32

# 2) stages on top of the warm start: gold-SFT control / VBI-FT / self-play
python -m train.finetune stages --name c1_vbi --fmt plan --init train/runs/e1_plan/adapter \
  --stages vbi --k 4 --hard_only --lr_vbi 1e-4 --exclude_n 1500 --n_round 1500 --rounds 1 --bs 32

# 3) full dev-set comparison (original vs. every adapter in train/evaluate.py's CHECKPOINTS list)
python -m train.evaluate
python -m train.evaluate --summary   # just print the table from saved metrics
```

See `train/finetune.py`'s module docstring for the exact commands `report/RQ3.tex`'s Table 16 chain was
built from, and `train/evaluate.py --help` for `--only`, `--zero-shot`, and `--summary`.

**VRAM.** The historical logs in `train/runs/*.log` / `*.out` show this chain running (with recoverable OOM
retries) on an 8 GB GPU; LoRA rank/alpha, batch size, and gradient checkpointing are already tuned for that.
On less than 8 GB, lower `--bs`.

## 6. Running the notebook

```bash
source .venv/bin/activate
pip install jupyter ipykernel   # if not already installed
python -m ipykernel install --user --name cisc451-a1
jupyter lab RQ1_RQ2_RQ3.ipynb   # or open it in VS Code / Cursor and pick the cisc451-a1 kernel
```

Run cells top to bottom from the repo root (the notebook asserts this via `report/main.tex`'s presence). It
performs steps 3–5 above itself — including live model inference and the full RQ3 fine-tuning chain — so
expect it to take hours end-to-end on first run; every heavy cell checks whether its output already exists
and skips the work if so, so re-running after an interruption only repeats what didn't finish. See the
notebook's own first cell for the full runtime/idempotency notes.
